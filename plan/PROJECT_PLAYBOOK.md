## 一、两句话讲清这个项目怎么做

### 知识点库不预先穷举，而是从真实错题里长出来

🔴 高数的定理公式有几十个，人工列不完也没必要 —— 薄弱点只能从真实错题里积累。



```
学生问一道 / 录一道错题
        ↓
系统归类：先匹配已有知识点；没有合适的就在章节下新建一个
        ↓
错题挂载到知识点上 → 掌握度随之更新 → 练习按薄弱点出
```

**两级结构解决"既要自由生长又不能乱"**：

| 层级 | 来源 | 数量 | 作用 |
|---|---|---|---|
| **第一层：章节** | 一次性写死（教材目录级） | 约 15 个 | 🔴 归类抽屉的标签，不是内容 |
| **第二层：具体知识点** | AI 在问答/归类时自动新建并挂靠 | 随使用增长 | 细节，按需生成 |

💡 **这 15 行不是知识库，只是抽屉的名字。** 设上限的唯一原因：不给边界，AI 会造出
「极限」「函数极限」「求极限」「洛必达」这种粒度并列的条目，掌握度统计随即作废。

| 层级 | 谁定 | 能不能改 |
|---|---|---|
| 章节 | 人一次性写死 15 个 | 🔴 AI 不许新增顶层分类 |
| 具体知识点 | AI 按题目动态创建 | ✅ 可新建，但必须先查重 |

另外：题目要求「把范围收窄」，这 15 个抽屉就是收窄的体现 —— 被问"怎么保证不超纲"，
答案是超出教材范围的题根本没有对应章节可挂。

AI 只能在已有的 15 个章节下创建子节点，且创建前先做相似度检查（"这个概念是否已存在"）。这样既不用人工穷举，又不会出现同义重复。
### 掌握度是估计值，不是正确率的简单除法

在基础正确率之外再乘两个因子：

```
掌握度 = 基础正确率 × 时间衰减 × 难度加权
   时间衰减：越久没练的知识点权重越低（间隔复习逻辑）
   难度加权：难题答对比易题答对更能证明掌握
```

对应官方加分项「按知识点给出掌握度估计」。

⚠️ 必须单独处理样本不足的情况 —— 新知识点没数据会被算成 0% 并霸占"最薄弱"榜首，导致练习一直推没人练过的题。

## 二、总排期

```
第 1~3 步 ──→ 第 4~5 步 ──→ 第 6~9 步 ──→ 阶段三 ──→ 缓冲 ──→ 阶段四
  环境准备     数据结构     ★三条主线打通   上线闭环   看懂代码   交付验收
  （阶段〇）    （阶段一）    （阶段二）
```

**各阶段的参考投入**（按你们实际速度伸缩，不设截止）：

| 阶段 | 步数 | 大约投入 |
|---|---|---|
| 〇 环境准备 | 第 1~3 步 | 每人合计 3~4 小时，主要是等安装和排查网络 |
| 一 数据结构 | 第 4~5 步 | 关键路径，C 卡住全组停 |
| 二 三条主线 | 第 6~9 步 | 最重的一段，约占全部编码量的一半 |
| 三 上线闭环 | — | 演示数据 + 部署 |
| 缓冲 | — | 🔴 别省。用来让每个人看懂 AI 写的代码 |
| 四 交付验收 | — | 几乎不写新代码，全是文档、复现测试、PPT |

必须留缓冲，因为两件事 AI 帮不上忙：**五个人把环境打通**（装软件、注册、等邮件验证、代理排查）；**每个人看懂自己交出去的东西**（答辩可能现场改代码）。后者拖到答辩前三天来不及。

## 三、五个阶段的目标与验收

| 阶段 | 覆盖步骤 | 结束标志（可验证） |
|---|---|---|
| **〇 环境准备** | 第 1~3 步 | 五人头像都在 Contributors；每人能起空白页面；每人都成功 push 过一次 |
| **一 数据结构** | 第 4~5 步 | 一条命令灌入 15 个归类抽屉；B 报告图片能不能识别；四人都说得出要调用对方哪个函数 |
| **二 三条主线** ⭐ | 第 6~9 步 | **录一道错题 → 归到某知识点（必要时新建）→ 问它涉及的知识点 → 得到讲解 → 掌握度变化**，整条链跑通 |
| **三 上线闭环** | 阶段三 | 把链接发给没参与的人，他自己能录题、做题、看到掌握度变化 |
| **四 交付验收** | 阶段四 | 陌生电脑照 README 从零跑通；PPT + 四份文档齐全 |

🔴 **阶段二是唯一的硬门槛。** 前面再顺，这条链跑不通就等于没做完。

### 功能优先级（按顺序做，不许四条并行）

```
🥇 第 1 优先  知识点问答（含动态建知识点）
🥈 第 2 优先  错题录入 + 归类 + 确认入库
🥉 第 3 优先  掌握度分析（含估计模型）
   ──── 以上三条做到就算达标 ────
     第 4     针对性练习（加分项，有余力才碰）
```

题目要求是**四条只需打通三条**。第四条做出来锦上添花，做不出来不影响及格线。

💡 **本项目 A 与 E 由同一人兼任。** 下表仍按两个角色分开写，方便看清哪些属于配置类工作 —— 执行时都是你一个人，但提交时要分成两条 commit（一条 docs、一条 chore），别混在一起。
| **B** | 模型调用封装、提示词设计与调优、抽取与问答逻辑 | `app/llm_client.py`、`app/prompts.py`、`app/qa.py`、`app/intake.py`（🔴 这四个只归 B） |
| **C₁** 🔴最先动 | 数据地基：表结构、连接管理、章节灌入、知识点动态挂载与查重 | `schema.sql`、`app/db.py`、`app/knowledge.py`、`data/chapters.json` |
| **C₂** | 统计与判定：输出校验器、掌握度估计、出题选池、判分回写、**离线自检脚本** | `app/schemas.py`、`app/profile.py`、`tests/` |
| **D** | 界面交互、桩函数体系、演示数据 | `streamlit_app.py`、`app/stubs.py`、`seed_data.py`、`data/question_bank.json` |

⚠️ **C₁ 是关键路径，但已经刻意拆薄了。** 原方案里一个人同时压着「表结构」「动态挂载」「掌握度估计」三件别人依赖的事，那是单点故障 —— 他卡两天全组停摆。

现在按**依赖顺序**而不是难度切：C₁ 只管"往里写、往外查原始数据"，C₂ 管"把查询结果算成掌握度"。两者之间隔着 `mastery_table()` 这条 SQL —— 只要第 5 步把列名定死并推送，两个人各干一半互不打架。

🔴 **A 要盯的只有两个交付点**：① C₁ 在第 5 步交出 `mastery_table()` 的列名定义（晚一天，C₂ 和 D 都只能靠桩）；② C₂ 从第 9 步起才成为关键路径，前面他有富余时间可以先搭校验器骨架。

### 分层边界（硬性，不许打穿）

```
streamlit_app.py    只做展示交互
                    🔴 不含业务逻辑、不发网络请求、不写 SQL
app/llm_client.py   🔴 全项目唯一允许发网络请求的文件
app/db.py           🔴 全项目唯一碰数据库的文件
app/prompts.py      所有提示词集中在这里
app/knowledge.py    知识点的查找 / 相似度匹配 / 新建挂靠逻辑（C₁）
```

好处：换模型供应商时只改 `.env` 三个变量，代码一行不动。

#### ⚠️ 高数特有的风险：公式识别

积分号 `∫`、极限 `lim`、上下限、分数结构 —— OCR 出错率明显高于高中数学这类简单公式。所以：

- 🔴 本步必须实测清楚，别拖到第 8 步
- **降级路径要提前准备好**：手输题干 + 允许粘贴 LaTeX 或纯文本表达式（如 `lim x->0 sin(x)/x`）
- 有可编辑确认表单兜底，识别错能手工改，不会导致流程断掉

```
□ 问一个本课概念 → 得到四段结构的讲解
□ 问一个越界问题（如英语作文）→ 被礼貌拒绝
□ 掌握度页面列出各知识点估计值，标出最薄弱的
□ 从没练过的知识点不会霸占"最薄弱"榜首
□ 自检脚本全绿
□ 提交历史里没有 .env、没有数据库文件、没有密钥
□ 五个人本阶段各有 ≥3 个真实功能提交，且没人说不清自己那块代码在干什么
```

## 六、协作机制：靠文件对齐，不开会

### 唯一的同步点：接口说明文档

```
组员 A 的 AI ←写→ docs/interfaces.md ←读→ 组员 B 的 AI
```

五个人各用各的电脑，各自的 AI 互不认识。**它们靠这份文件对接，不靠对话。**

```
C 写完 → 提交推送 → 群里说一句「数据结构定了，pull 一下」
                    ↓
其他人 pull，自己的 AI 读接口文档就能开始干活
有异议 → 群里说，改的人更新文档再提交一次
```

**三条配套规矩**：

1. 改了函数名 / 参数 / 返回值 → **同一次改动里更新接口文档**，并单独提交一条 `docs: 更新接口契约（xxx）`
2. 要用队友的功能就读文档 + 读源码，**不要让两个 AI 互相传话**（AI 之间转述必丢信息）；有疑问直接在群里问人
3. 每天收工时让 AI 生成三句话总结发群里 —— 这才是队友的 AI 能消费的信息

### 关键技巧：用桩函数消灭等待

新手团队最大的时间黑洞是串行依赖。解法：

```text
C 的真函数还没写好。请在 app/stubs.py 里造一个假的 mastery_table()，
返回预期形状的数据，让我先把界面跑起来。
等真接口就绪后我只需要换 import 来源，界面代码不动。
```

这一招能把"四个人互相等"变成"四个人同时干"。

### 每天的固定动作

**开工**（新开对话时 AI 什么都不记得，先发这段）：

```text
我要继续推进这个项目。请按顺序做完再等我下指令，不要修改任何业务代码：
1. git pull
2. 读 docs/interfaces.md，告诉我这次要做的那部分需要调用哪些函数、吃什么吐什么
3. 打开那些函数的源码，用大白话逐段解释
4. 跑 tests/offline_check.py，把结果贴给我
```

第 4 步很关键 —— **自检红了说明 main 是坏的**，先报告别硬写。

**收工**：

```text
今天到此为止，做四件事：
1. git status 看改了哪些文件，逐个 add 并 commit，message 按规范写
2. 如果我改过任何函数的名字/参数/返回值，同步更新接口文档，单独提交一条
3. git push 到我的分支，把终端给出的链接告诉我
4. 用三句话总结今天改了什么，不要贴代码 —— 我要发群里
```

## 七、Git 规矩

🔴 **每次完成一部分功能就 commit 一次，commit message 说清楚这次改了什么。**
这条不是形式：官方会直接 clone 仓库看提交历史，「分多次提交而不是最后一次性上传」
是写在题目里的硬性要求，也是最能看出真实开发过程的地方。

```bash
# 每天
git pull                              # 开工第一件事，永远
git add <你改的那个文件>               # 🔴 别用 git add .（会带上别人的改动和 .env）
git commit -m "feat(m2): 支持拍照录入错题"
git push                              # 收工最后一件事 + 群里报一声

# 分支命名：只能用大小写字母、数字和 - _ . /
test/<缩写>   feature/<名字>   fix/<名字>   docs/<名字>

# commit type
feat 新功能 · fix 修 bug · docs 文档 · refactor 重构 · test 测试 · chore 构建
✅ "feat(knowledge): 支持在章节下动态新建知识点并做相似度去重"
❌ "update" / "111" / "改了点东西"
```

| 规矩 | 原因 |
|---|---|
| main 开了分支保护，直推会被拒 | 报错里有 `protected`/`GH006` 字样就是规则在起作用，不是你操作错了 |
| **PR 创建和 Merge 由组长做** | 收口点只留一个，出问题好定位。组员 push 完报一声即可 |
| 🚫 全组禁用 `git push --force` | 会覆盖远端历史、抹掉别人的提交，极难恢复 |
| 🚫 不要用格式化工具重排整个文件 | 几百行无关 diff，冲突时几乎无法手工合并 |
| 🚫 不提交 `.env`、数据库、数据集、缓存、IDE 配置 | 密钥泄漏是最严重的事故 |
| ✅ 每周每人至少 3 个真实功能提交 | 官方原话"我们会直接克隆你的仓库并尝试运行"，一把梭最容易失分 |
| ✅ 撤销已推送的改动用 `git revert` | 生成新提交不改历史；别用 force push 修主干 |
| ✅ 冲突时人来决定 | 让 AI 列出双方内容，**不要让它替你选** |

## 八、砍功能的触发线

新手项目死于"想做太多"的概率远高于死于"做得太少"。到点就砍，不犹豫：

| 检查时机 | 如果… | 就… |
|---|---|---|
| **第 5 步结束时** | 数据结构还没定 | **砍掉第四个功能**，只做三条 |
| **第 9 步结束时** | 问答还跑不通 | 界面降级成最简两栏问答，先保证有个能动的东西 |
| **第 9 步结束时** | 公式识别一直不准 | 明确走手输 + 粘贴表达式路径，照样能落库和统计 |
| 任何时候 | 有人提"要不要加登录/多用户" | **不加** |
| 任何时候 | 有人说"要不把知识点库人工补全吧" | 🔴 **不做**。这违背本项目的核心设计 —— 知识库就该从真实错题里长出来 |
| 任何时候 | 有人说"再加个 RAG 吧" | 不做，它会吃掉整周 |

## 九、交付物清单

### 阶段三 · 上线闭环

```
1. 演示数据：≥30 条像样的错题 + 对应的动态知识点
   🔴 分布刻意安排 —— 两三个知识点明显差、几个中等、几个好，

2. 部署到公网拿到链接
3. 第四个功能：按薄弱点出题 → 作答 → 判分 → 做错的回到错题本
```

| 优先级 | 事项 |
|---|---|
| 🥇 | **每个人把自己那层代码看懂** —— 让 AI 逐段讲解，看不懂就在群里问 |
| 🥈 | 补做前面砍掉的功能 |

🔴 **进入交付阶段第一件事：陌生电脑复现测试**。找一台从没开发过的机器，只照 README 操作跑到底。跑不通的地方就是文档要补的地方。官方原话"评审会按文档从零执行一遍"。

| 项 | 负责人 |
|---|---|

## 十、卡住了怎么办

| 情况 | 动作 |
|---|---|
| 连不上 GitHub / push 被拒 | 群里贴**报错原文**（整段红字，不要截断不要转述），别自己试第五种方法 |
| AI 改了不该改的文件 | 立即叫停："撤销刚才所有改动"，重新说清边界 |
| 同一个错误连续三轮没解决 | 停止，求助 |
| 队友函数还没好 | 用桩函数先跑自己的部分，别干等 |
| 累计卡住超过 90 分钟 | **必须求助**，闷头耗是最贵的 |
| 不知道它为什么这么写 | 当场追问，别拖到晚上 |

### 提问的两条纪律

1. **每次开头带这句**：`先列方案，不要直接改文件。`
   价值不在于选对方案，而在于**在它动手前发现它理解错了**。
2. **跑通之后必发这句**：
   ```text
   逐段用大白话解释刚才写的代码。标出哪里调外部服务、出错怎么办、
   哪些数字是规则阈值。然后出 3 道题考我。
   ```
   成本 30 秒，收益是你三个月后还知道自己交的是什么。
